# Contributing

Thanks for your interest in contributing.

## Ground Rules
- Keep PRs small and focused.
- Follow Clean Architecture boundaries (API/Application/Domain/Infrastructure).
- Add or update tests when changing behavior.
- Update docs for architectural changes (see /docs and ADRs).

## Workflow
1. Create a branch: `feat/...` or `fix/...`
2. Commit messages: `feat:`, `fix:`, `docs:`, `ci:`, `refactor:`
3. Open a PR to `main`
4. Ensure CI is green

## Code Style
- Prefer clarity over cleverness.
- Avoid business logic in API controllers.
